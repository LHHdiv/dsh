第17章 长期演进路线图

阶段一 私有工具（你能动它了）

🎯
本文学系目标规划长期演进：私有工具 → 个人知识库/记忆 → 多 Agent 协作 → 终身自治。

第17章 长期演进路线图

这一章把"让 dsh 成为你终身个人 Agent"的宏大目标，拆成四阶段路线图。每一阶段都有明确的产出、对应的本书章节，以及"该在哪个扩展点动手"。

17.1 总览

阶段一  私有工具（你能动它了）
   │
阶段二  个人知识库 / 长期记忆（它记得你了）
   │
阶段三  多 Agent 协作（它能分工了）
   │
阶段四  终身自治（它开始自我改进）

每阶段都建立在上阶段之上，且都遵守同一原则：全部用插件扩展，核心零改动。

17.2 阶段一：私有工具（✅ 你已完成）

产出：my_notes 工具 + my-personal 预设。 对应章节：第 11、14、15 章。 扩展点：ctx.tools.register(defineTool(...)) + preset 组合。

验收：对话中模型能调 my_notes 读取你的笔记。

后续可选增强： - 给 my_notes 加 write/append 动作——让它既能读也能写； - 加第二个工具（如"待办管理"，可参考 packages/todo/tool-todo 的"整体列表替换"模式）。

17.3 阶段二：个人知识库 / 长期记忆（推荐下一步）

目标：Agent 能"记得"你跨会话的重要信息，不再一问就忘。

思路（详见第 16 章实例一）： 1. 把 ~/dsh-notes 升级成"结构化知识库"：笔记加 frontmatter（日期、标签、类型）； 2. 新增一种 SessionEvent（如 memory/upsert），在 agent/pre-step 时检索相关笔记注入上下文； 3. 遵守"模型可见即已记录"铁律：注入内容从日志可重建； 4. 可选：加一个 memory_search 工具，让模型主动检索而非被动注入。

产出：一个会"记住你偏好与事实"的私人 Agent。 扩展点：SessionEventMap 扩展 + agent/pre-step 监听。

这是把 dsh 从"通用工具"变成"你的 Agent"最实质的一步。

17.4 阶段三：多 Agent 协作

目标：一个主 Agent 负责统筹，多个子 Agent 各自干专活（研究、写作、执行），互不污染上下文。

思路（第 16 章实例二）： - 用 packages/subagent 的子代理能力；主 Agent 通过 tool-subagent 委派子任务； - 每个子 Agent 用独立的 scope/预设，拥有自己的工具集与人设； - 主 Agent 只汇总结果，保持主上下文干净。

产出："研究助理 / 写作助手 / 执行专员"分工的个人工作台。 扩展点：ctx.subagent + tool-subagent + preset。

17.5 阶段四：终身自治（长期愿景）

目标：Agent 能维护自己的文档、规划自己的改进，并在你的许可下执行"自我升级"。

思路： - 结合 workflow（工作流引擎）把"例行任务"固化成可重复流程； - 结合 plan（计划模式）让 Agent 先出方案、你审批再执行； - 把 dsh 自己的 AGENTS.md / docs/ 喂给它，让它"懂自己"； - 用 hooks 机制接入外部自动化（比如定时复盘、周报）。

产出：一个能"自维护、自演进"的个人 Agent——但决策权永远在你（审批机制兜底）。

17.6 每个阶段都要做的事

  1. 学：读懂对应章节与源码；
  2. 写：做成插件（复用"套路"）；
  3. 验：本地跑通、写进学习文档（chapters/ 新增一篇）；
  4. 稳：跟踪上游更新，插件与核心解耦，升级不慌。

17.7 对"简单"的正视

你最初说"这个项目还比较简单"。这是事实，也是好事：

  • 简单 = 能看清全貌，学习成本低；
  • dsh 是 developer preview，迭代快——意味着它会变复杂，而你已经掌握了它的扩展心智；
  • 你现在打的地基（插件套路、事件模型、会话日志纪律），未来完全复用。

17.8 小结

  • 四阶段：私有工具 → 知识库/记忆 → 多 Agent → 终身自治。
  • 每一阶段 = 一个标准扩展点 + 一个插件；核心永不动。
  • 下一阶段建议：阶段二（长期记忆），它让 dsh 真正"成为你的"。

最后一章：回顾全书，给你一份"读完这本书之后"的行动清单。

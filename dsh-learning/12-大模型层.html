第12章 LLM 能力层（llm provider）

前面把"工具"讲透了。现在看另一端：模型本身是怎么被接进 dsh 的？答案是 llm 包的 seam（能力接缝） 设计。

12.1 什么是 seam（接缝）

架构文档给了一个重要概念（第 98–100 行）：

A seam is a swappable capability with three roles: a Service Definition declaring the interface, a Service Provider implementing it, and a Consumer using it.

一个可替换能力，由三角色组成：

角色 含义 在 LLM 里
Service Definition 声明接口 LlmRuntime（ctx.llm）
Service Provider 实现接口 DeepSeek 适配器
Consumer 使用它 agent-loop（调用模型）

关键点：一个 provider 的替换，能改变整个产品的行为。 比如把 DeepSeek 换成另一个模型，只要换 Provider，上层完全不用动。

12.2 Service Definition：ctx.llm

packages/llm/llm 拥有 ctx.llm，类型叫 LlmRuntime。它提供：

  • registerAdapter(providers, adapter)：注册一个模型适配器；
  • registerConfigurableProviders([...])：声明可配置的 provider 路由；
  • prepareCall(...) / stream(...)：发起一次流式调用；
  • 事件 llm/stream（waterfall）：可被监听做缓存/日志/路由。

它的 README 明确说：ctx.llm 是"适配器注册表 + 单一流式调用 API，可被瀑布事件拦截"。

12.3 Service Provider：DeepSeek 适配器

适配器基类 LlmAdapter 在 packages/llm/llm/README.md 定义，唯一必须实现的方法是 stream()。

具体实现 DeepSeekAdapter：

  • 类定义：packages/llm/llm-deepseek/src/adapter.ts（第 160 行）
  • 注册消费（插件 apply）：packages/llm/llm-deepseek/src/index.ts（第 256 行）
// packages/llm/llm-deepseek/src/index.ts（示意）
const registration = ctx.llm.registerAdapter([PROVIDER], adapter)   // PROVIDER='deepseek-official'
ctx.llm.registerConfigurableProviders([
  { provider: PROVIDER, displayName: 'DeepSeek', settingsNs: NS, settingsPath: [] },
])

可以看到：Provider 插件只是往 ctx.llm 注册了一个适配器，核心循环并不知道"背后是哪个模型"。

12.4 凭据从哪来

LLM Provider 需要 API Key。dsh 的凭据解析走 credentials 服务，回退到进程环境变量 DEEPSEEK_API_KEY（index.ts 第 225–246 行）。缺失时抛 MISSING_CREDENTIAL。

小白意义：你永远不该把密钥写进代码。dsh 通过 credentials 服务 + 环境变量解耦，安全且可配置。

12.5 Consumer：谁在调用模型

LLM 的消费者，就是 Agent 主循环（agent-loop）——它在 buildRequest/step 里调用 ctx.llm.prepareCall(...) 与 stream(...)（见第 13 章）。此外，llm/stream 的瀑布监听者（如 dsh-llm-retry 做重试）也是消费者。

这就形成一个清晰闭环：

agent-loop (Consumer) ──prepareCall/stream──► ctx.llm (Definition)
                                              │
                              registerAdapter ► DeepSeekAdapter (Provider)

12.6 为什么这套设计对你重要

回到你的目标：想让 dsh 成为"你的"Agent。seam 设计意味着——

  • 想换/加模型？写一个新的 Provider 插件注册到 ctx.llm，不动核心；
  • 想给所有模型调用加日志/缓存/限流？监听 llm/stream 事件；
  • 想让不同会话用不同模型？在预设里配置 llm-deepseek: 段即可。

一切又回到了"挂插件"，而不是改核心。

12.7 小结

  • LLM 层是个 seam：Definition=ctx.llm、Provider=DeepSeek 适配器、Consumer=agent-loop。
  • Provider 只需实现 stream()，经 registerAdapter 注册；换模型 = 换 Provider。
  • 凭据走 credentials 服务，回退 DEEPSEEK_API_KEY。

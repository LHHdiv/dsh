第7章 本地把项目跑起来

学项目最快的方式，是先让它跑起来。本章给你可复制的命令和关键机制解释。

7.1 环境要求

  • Node.js：^22.19 || >=24（dsh 用到了较新的 Node 特性）。
  • pnpm：项目用 pnpm workspaces 管理多包。
  • 一个 DeepSeek API Key（真实对话需要）：环境变量 DEEPSEEK_API_KEY。

7.2 从源码运行（推荐你这样跑）

# 1) 进入项目
cd /path/to/deepseek-harness      # 即本仓库根目录

# 2) 安装依赖（pnpm workspaces）
pnpm install

# 3) 启动 Web UI（默认 http://127.0.0.1:3080）
pnpm dsh web

打开浏览器访问 http://127.0.0.1:3080，你就拥有了 dsh 的聊天界面。

如果你的机器装过旧依赖或构建产物混乱，可先 pnpm run clean 再 pnpm install。

7.3 其它运行方式

# 一次性运行某个任务（无界面，需 DEEPSEEK_API_KEY）
pnpm dsh --profile headless "帮我写一个快速排序并用中文讲解"

# 构建（可选；开发时其实可以免构建直接跑源码，见 7.5）
pnpm run build

7.4 凭据与环境变量

变量 作用
DEEPSEEK_API_KEY 真实调用 DeepSeek 模型（必需）
DEEPSEEK_BASE_URL 可选，自定义模型服务地址
$DSH_HOME 可选，覆盖 dsh 的家目录（默认 ~/.dsh）

凭据也可写入 $DSH_HOME/.credentials.yaml，或在 $DSH_HOME/settings.yaml 里配置 llm-deepseek: 段。切勿把密钥提交进 git。

7.5 关键机制：免构建的源码启动（重点）

这是 dsh 对学习者最友好的设计之一，务必理解。

根 package.json 里的 dsh 脚本其实是：

"dsh": "node --import tsx/esm apps/cli/src/bin.ts"

也就是说，pnpm dsh web 走的是 tsx 的 ESM hook（node --import tsx/esm），直接运行 .ts 源码——不需要先 pnpm run build 生成 lib/。

那 Node 怎么解析 @deepseek-ai/dsh-xxx 这些包名？答案是 tsconfig.base.json 里的 paths 映射：

"paths": {
  "@deepseek-ai/cordis":               ["./vendor/cordis/src"],
  "@deepseek-ai/dsh-tool-my-notes":    ["./packages/notes/tool-my-notes/src/index.ts"],
  "@deepseek-ai/dsh-tool-todo":        ["./packages/todo/tool-todo/src/index.ts"]
  /* …每个包都有对应映射… */
}

于是 tsx 在解析这些包名时，直接命中 packages/*/src，无需 lib/ 构建产物。

小白意义：你改了某个包的 src/index.ts，只要重启 pnpm dsh web 就能生效，不用重新构建。这让你"边读源码边改、立刻看到结果"，学习反馈极快。

7.6 跑起来后，你看到了什么

Web UI 里通常能：新建对话、选择/切换预设（preset）、看到工具调用过程。记住"预设"这个词——第 14 章会专门讲它，而你前面加的 my-personal 预设，就是通过 settings.yaml 把它设成了默认。

7.7 小结

  • 跑起来：pnpm install → pnpm dsh web → 打开 127.0.0.1:3080。
  • 凭据用 DEEPSEEK_API_KEY；别提交密钥。
  • 免构建源码启动：tsx + tsconfig paths 让你改 src 即生效，学习反馈最快。

第15章 实战：写第一个私有工具 my_notes

前面所有章节的"理论"，这一章全部用上：你亲手给 dsh 加一个只属于你的私有工具。 我们分两步：先讲改动逻辑（改了哪几处、为什么），再逐行讲代码。

15.1 我们要做什么

给 dsh 加一个工具 my_notes：它可以 list / read / search 你 ~/dsh-notes/ 目录下的 Markdown 笔记。效果：模型在对话里"多了一双手"，能翻你的私人笔记。

你: 我上周记过关于 Vue 的想法，帮我找找
模型: (调用 my_notes search keyword=Vue)
   → 返回命中行
模型: 找到了，你在 xxx.md 里写过……

15.2 改动逻辑：一共动了哪几处（先看地图）

完整地"把一个新工具接进 dsh"，需要 5 处改动。只有第 1 处是写新代码，其余都是"接线"（配置）——这正是"一切皆插件"的落地形态：

# 文件 做了什么 为什么
1 packages/notes/tool-my-notes/（新建包） 写了插件的 package.json / tsconfig.json / src/index.ts 工具 = 一个 Cordis 插件，代码就在这里
2 ~/.dsh/settings.yaml agent-presets.default: my-personal 让"我的私人 Agent"成为默认预设（覆盖出厂 standard）
3 ~/.dsh/.agent-presets/my-personal/agent.cordis.yml 组合里加一行：- id: tool-my-notes / name: '@deepseek-ai/dsh-tool-my-notes' 把你的工具挂进私人预设，新会话自动带上它
4 tsconfig.base.json paths 加映射：@deepseek-ai/dsh-tool-my-notes → packages/notes/tool-my-notes/src/index.ts 免构建源码启动时，Node 能解析到你的包（见第 7 章）
5 packages/bundle/web-app/package.json dependencies 加 @deepseek-ai/dsh-tool-my-notes: workspace:^ 满足配置门禁（verify-cordis-config）检查，供构建/CI 使用

核心结论：packages/ 里的核心代码，一行都没改。加能力 = 写一个自己的包 + 在配置里"挂"一下。

15.3 逐行讲解源码

文件：packages/notes/tool-my-notes/src/index.ts（共 157 行）

15.3.1 头部注释与导入（1–24 行）

import { readdir, readFile, stat } from 'node:fs/promises'
import { homedir } from 'node:os'
import { join } from 'node:path'
import type { Context } from '@deepseek-ai/cordis'
import z from '@deepseek-ai/schemastery'
import { defineTool } from '@deepseek-ai/dsh-tools'
  • 前三个是 Node 内置模块（读目录、读文件、拼路径），不需要安装任何东西；
  • Context 是 Cordis 的插件上下文类型；
  • schemastery 是 dsh 用的 schema 库（校验配置）；
  • defineTool 来自 @deepseek-ai/dsh-tools（第 11 章讲过）。

15.3.2 插件三件套：name / inject / apply（26–29 行）

export const name = 'tool-my-notes'
export const inject = ['tools']
  • name：插件唯一标识（loader 靠它识别本模块是插件）；
  • inject: ['tools']：声明"我需要 ctx.tools 服务先就绪"——框架据此安排加载顺序。

15.3.3 配置（31–46 行）

export interface Config { root?: string }

export const Config: z<Config> = z.object({
  root: z.string().default(join(homedir(), 'dsh-notes')),
})

function notesRoot(config: Config): string {
  const fallback = join(homedir(), 'dsh-notes')
  return config.root?.trim() ? config.root.trim() : fallback
}
  • 接口 Config 声明"可选字段 root（笔记目录）"；
  • z.object(...) 用 schemastery 描述配置，缺省值默认 ~/dsh-notes；
  • notesRoot()：优先用用户配置，否则回退默认。?.trim() 防止空字符串覆盖默认。

15.3.4 两个小工具函数（48–68 行）

async function listNotes(root: string): Promise<string[]> {
  let entries: string[]
  try {
    entries = await readdir(root)
  } catch {
    return []          // 目录不存在 → 当作没有笔记，不报错
  }
  const files: string[] = []
  for (const entry of entries) {
    if (!/\.(md|markdown)$/i.test(entry)) continue
    if ((await stat(join(root, entry))).isFile()) files.push(entry)
  }
  return files.sort()
}

function ok(text: string) {
  return Promise.resolve({ result: text })   // 统一返回 { result: 文本 }
}
  • listNotes：列目录 → 只保留 .md/.markdown 文件 → 排序；目录不存在返回空数组（友好处理）；
  • ok()：把结果包成 { result: text }——与下面 output.schema 对应。

15.3.5 插件入口 apply（70–157 行）

export function apply(ctx: Context, config: Config): void {
  const root = notesRoot(config)
  ctx.tools.register(defineTool({

apply 是 Cordis 挂载插件时调用的入口；这里做且只做一件事：往工具表注册一个工具。

    name: 'my_notes',
    description:
      '读取并检索你的个人 Markdown 笔记（位于 ' + root + '）。'
      + '可用动作：list 列出全部笔记文件名；read 读取某篇笔记全文（需提供 name）；'
      + 'search 在所有笔记中按关键词搜索并返回命中行（需提供 keyword）。'
      + '当你需要回忆、查找或引用之前记下的内容时使用。',

description 是给模型看的"使用说明书"——模型靠它决定"什么时候该调这个工具"。写清楚动作与参数，模型才知道怎么用。

    parameters: {
      action: {
        type: 'string', required: true,
        description: '要执行的操作：list | read | search',
        enum: ['list', 'read', 'search'],
      },
      name:    { type: 'string', description: 'read 时的笔记文件名（可选）' },
      keyword: { type: 'string', description: 'search 时的关键词（可选）' },
    },
  • action 必填 + enum 限定三种操作；
  • name、keyword 可选——注意：可选参数省略 required 键（第 11 章的坑，这里就是正确示范）。
    output: {
      schema: {
        type: 'object', additionalProperties: false,
        properties: {
          result: { type: 'string', required: true, description: '工具返回的可读文本' },
        },
      },
      render: (_args, value) => [{ type: 'text', text: value.result }],
    },
  • output.schema 声明返回结构；render 决定对话里如何展示（把 result 渲染成文本块）。
    async execute(args) {
      const { action, name: fileName, keyword } = args as {
        action: 'list' | 'read' | 'search'
        name?: string
        keyword?: string
      }

execute 是模型真正调用工具时执行的函数。第一行解构参数：把 name 重命名成 fileName（避免和上面的工具名混淆）。

      if (action === 'list') {
        const files = await listNotes(root)
        if (files.length === 0) return ok(`笔记目录 ${root} 下还没有任何 .md 笔记。`)
        return ok('我的笔记列表：\n' + files.map(f => `- ${f}`).join('\n'))
      }

list：列出文件名，空目录给友好提示。

      if (action === 'read') {
        if (!fileName) throw new Error('read 操作需要提供 name（笔记文件名）')
        const full = join(root, fileName)
        let content: string
        try {
          content = await readFile(full, 'utf8')
        } catch {
          throw new Error(`找不到笔记 ${fileName}（预期路径：${full}）`)
        }
        return ok(`# ${fileName}\n\n${content}`)
      }

read：先校验参数（缺 name 直接抛错，错误会回给模型让它纠正），再读文件；读不到给出带预期路径的错误信息——模型能看到并自行调整。

      if (action === 'search') {
        if (!keyword) throw new Error('search 操作需要提供 keyword（关键词）')
        const needle = keyword.toLowerCase()
        const files = await listNotes(root)
        const hits: string[] = []
        for (const file of files) {
          const lines = (await readFile(join(root, file), 'utf8')).split('\n')
          lines.forEach((line, i) => {
            if (line.toLowerCase().includes(needle)) {
              hits.push(`${file}:${i + 1}: ${line.trim()}`)
            }
          })
        }
        if (hits.length === 0) return ok(`在笔记中没有找到包含「${keyword}」的内容。`)
        return ok(`在笔记中找到 ${hits.length} 处匹配：\n` + hits.join('\n'))
      }

      throw new Error(`未知的操作 ${String(action)}，仅支持 list / read / search`)
    },
  }))
}

search：逐文件逐行找关键词（toLowerCase 让大小写不敏感），返回 文件:行号: 内容 列表，模型据此精准引用。兜底抛错处理未知 action。

15.4 你学到的"套路"（请记住这条）

在 dsh 里加一个工具 = 写一个插件包（name/inject/apply + defineTool），再在预设配置里挂一行。核心一行不改。

这套套路从 tool-todo、tool-fs 到你自己的 my_notes，全都一样。学会它，你就掌握了 dsh 80% 的扩展方式。

15.5 验证清单

  1. mkdir -p ~/dsh-notes && echo "# 测试" > ~/dsh-notes/welcome.md
  2. 重启 pnpm dsh web，开新会话；
  3. 依次问：用 my_notes 列出我的笔记、读一下 welcome、搜索包含 测试 的内容；
  4. 看到工具被调用并正确返回，即接线成功。

15.6 小结

  • 5 处改动：1 处新代码（插件包）+ 4 处接线（settings / preset / tsconfig / package.json）。
  • 核心代码零修改；工具 = 插件 = defineTool 注册到 ctx.tools。
  • required: true 只用于必填；可选参数省略 required。

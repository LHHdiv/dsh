🎯

第16章 如何给 dsh 加能力

你已经会加工具了。这一章把"加能力"这件事系统化：dsh 给每个目标都预留了标准扩展点。记住一句话：先找扩展点，再挂插件；绝不改核心。

16.1 官方扩展点映射表

来自 docs/architecture.md 的"Where new behavior goes"，这是你以后做任何改动的第一查表：

你的目标 机制（扩展点）
加一个模型 provider 在 ctx.llm 上注册适配器
加一个模型可见能力 注册到 ctx.tools；其 schema 自动进入提示组装
给某个会话不同的能力集 组合一个 agent preset（service 行需 isolate realm）
加 Shell 执行 注册 ctx.shell 后端（本地实现经由 ctx.subprocess）
加持久终端执行 注册 ctx.terminals 后端 + dsh-tool-terminal
加人工命令 注册到 ctx.commands（不走模型回合）
加后台任务 注册到 ctx.jobs（job_* 工具收集/停止）
加文件系统访问或策略 注册 ctx.fs provider，或监听 fs/* 事件
限制子进程 用 ctx.sandbox 后端
拦截请求/工具/回合 监听 agent/* 或 tools/* 事件（agent/turn-stopping 可停回合）
给模型注入上下文 调 agent.inject()，落入下一个被接受的请求
加 UI / 编辑器集成 驱动 ctx.agents，从 session/event 渲染
加持久会话状态 扩展 SessionEventMap，从日志渲染与回放
生成会话标题 注册唯一的 ctx.sessionTitle provider
分叉实时会话 ctx.sessions.fork(source, boundary?, childSessionId?)
让注册只作用于某 agent 用该 agent 的 agent.ctx

16.2 三个最常见的"加能力"实例

实例一：给 Agent 加"长期记忆"（推荐你的下一步）

模型是无状态的（第 1 章）。要让它"记得你"，正确做法是扩展会话事件，而不是塞 prompt：

  1. 在 SessionEventMap 里新增一种事件（如 memory/upsert）；
  2. 写一个插件：在 agent/pre-step 时，从你的记忆存储检索相关内容，注入进本轮输入；
  3. 按"模型可见即已记录"铁律：注入的内容也要能在日志中重建（渲染自事件）。

为什么不能只塞 prompt？因为那会违反 deriveMessages 的不变式，且不可回放、不可持久。dsh 的架构在"逼"你用正确的方式加记忆。

实例二：给 Agent 加"子 Agent"（委派）

packages/subagent 提供子代理能力：

  • ctx.subagent 服务定义子代理接口；
  • tool-subagent 是一个模型可见工具——模型可以把一个子任务委派给一个全新上下文的子 Agent，再把结果拿回来。

适合：把一个"多步骤、易污染主上下文"的任务拆出去，让主 Agent 保持专注。

实例三：加一个"模型 provider"

  1. 写一个类继承 LlmAdapter，实现 stream()；
  2. 在插件 apply 里 ctx.llm.registerAdapter(['my-provider'], adapter)；
  3. 加配置项（registerConfigurableProviders），密钥走 credentials 服务。

上层（主循环、工具、UI）完全不用动——这就是 seam 的威力（第 12 章）。

16.3 判断"改哪一层"的心法

拿到一个新需求，按这个顺序问自己：

  1. 它是不是一个新的"能力"？ → 写插件，注册到对应 ctx.<key>。
  2. 它是不是"横切"（日志、鉴权、缓存）？ → 监听对应事件（agent/*、tools/*、llm/stream）。
  3. 它是不是"这个会话专属"？ → 放进预设组合（preset），别全局注册。
  4. 它要不要"模型看到"？ → 要：做成工具或事件注入；不要：做成普通服务/命令。
  5. 如果非改核心不可？ → 停下来。多半是你没找到正确扩展点。回查上表。

16.4 官方 cookbook（进阶自助入口）

docs/cookbook/ 里有逐步指南，你之后可以自助查阅：

  • adding-a-tool.md（加工具）、adding-an-llm-adapter.md（加模型适配器）、adding-a-package.md（加包）、adding-a-conversation-node.md（加 UI 节点）、adding-a-settings-card.md（加设置卡片）。

16.5 小结

  • 所有扩展都有标准扩展点：注册服务 / 监听事件 / 组合预设 / 扩展会话事件。
  • 加记忆 = 新 SessionEvent + 从日志渲染（遵守铁律）。
  • 改不动就查 architecture.md 的扩展点表，或读 cookbook。

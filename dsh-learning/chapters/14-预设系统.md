# 第14章 预设系统（preset）与默认覆盖

> 这一章回答一个你亲身体验过的问题：**为什么改一个 `settings.yaml`，你的 Agent 就从"官方标准"变成了"我的私人 Agent"？** 答案是预设系统，而且**零核心改动**。

## 14.1 什么是预设（preset）

**预设 = 一套"插件 + 工具 + 人设"的组合模板**。它决定一个新会话默认加载哪些插件、哪些工具、用什么人设。

- **出厂预设**在 `apps/cli/config/agent-presets/standard/`（`agent.cordis.yml` + `preset.yml`）；
- **用户预设**放在 `~/.dsh/.agent-presets/`（你之前建的 `my-personal` 就在这里）；
- 预设由 `packages/preset/agent-presets` 负责发现、解析与挂载（`ctx.agentPresets`）。

## 14.2 关键公式：defaultId

`packages/preset/agent-presets/src/index.ts`（第 191–193 行）里有一行决定"默认用哪个预设"：

```ts
get defaultId(): string {
  return this.settings?.get().default ?? this.config.default
}
```

翻译成大白话：

> **默认预设 = 用户设置里的 `default`；没设置的话，才用出厂配置里的 `default`。**

这就是"零改核心"的秘诀：`config.default`（出厂默认 `standard`）写在 `packages/bundle/web-app/cordis.patch.yml`（421–424 行）里，但你通过 `settings.yaml` 写一个更高的优先级：

```yaml
# ~/.dsh/settings.yaml
agent-presets:
  default: my-personal
```

于是 `defaultId` 返回 `my-personal`，你的私人预设成为默认——**核心一行没改**。

> 注意：`defaultId` 是每次调用都重新读取的（源码第 187–189 行有注释），所以改 `settings.yaml` 后**热重载即生效**，这就是为什么"改完 settings 重启 `pnpm dsh web`"就能看到效果。

## 14.3 settings.yaml 从哪读

`packages/settings/settings-file/src/index.ts`（第 56 行）：

```ts
const filename = resolve(config.path ?? join(resolveDshHome(config.dshHome), 'settings.yaml'))
```

默认路径是 **`<harness home>/settings.yaml`**，而 harness home 由 `packages/util/home-paths` 决定：`$DSH_HOME` 优先，否则 **`~/.dsh`**。所以默认就是 `~/.dsh/settings.yaml`。它还带 `chokidar` 文件监听（第 237 行起），实现热重载。

## 14.4 用户预设放哪

`packages/preset/agent-presets/src/discovery.ts`（第 41 行）：

```ts
export const USER_PRESET_DIR = '.agent-presets'
```

预设系统把 `{ path: dshHomePath(USER_PRESET_DIR), trust: 'user' }` 追加为"用户信任根"（默认开启），即 **`~/.dsh/.agent-presets`**。你的 `my-personal` 预设目录就放在这里，天然被系统发现。

## 14.5 预设的 agent.cordis.yml 在"组装"什么

以出厂 `standard/agent.cordis.yml` 为例，它是个 **agent-plane 组合**：把一堆插件与工具按功能分区挂进"常驻作用域"，每个会话通过 scope 父子关系共享这些工具与提示段。分区大致是：

- identity：`persona`、`agent-instructions`（人设与指令 → 系统提示段）；
- shell：`tool-bash`、`tool-pwsh`（用 `disabled: !!js process.platform === 'win32'` 做条件装载）；
- filesystem：`tool-fs`、`tool-fs-search`；
- background jobs：`tool-jobs`；skills：`skill-filesystem`、`tool-skill`；goals 等。

你在 `my-personal/agent.cordis.yml` 末尾加一行：

```yaml
- id: tool-my-notes
  name: '@deepseek-ai/dsh-tool-my-notes'
```

就是把你的私有工具**挂进这个组合**——新会话自动带上它。

> 一条硬约束（注释里写了）：预设里的 **service 行必须放进带 `isolate` realm 的 group**，否则会发布到 root realm 造成进程级全局冲突，`dsh-agent-presets` 挂载时会拒绝。记住：**写预设时，工具行放 group 里，别裸挂在顶层**。

## 14.6 为什么这对你特别重要

预设系统 = **不碰核心、用配置定制 Agent** 的完整通道：

- 换人设：改 `agent.cordis.yml` 里的 persona 段；
- 加工具：在预设组合里加一行；
- 换默认：改 `settings.yaml` 的 `default`；
- 想要多个 Agent：建多个预设，切换即用。

你的整个"个人 Agent"路线，都建立在"预设 + 插件"这两块积木上。

## 14.7 小结

- `defaultId = settings['agent-presets'].default ?? config.default`——用户设置覆盖出厂默认，零改核心。
- 设置存于 `~/.dsh/settings.yaml`（热重载）；用户预设放 `~/.dsh/.agent-presets/`。
- 预设 = 插件/工具/人设的组合模板；加工具就是在组合里加一行。

# 第10章 会话日志与系统提示

> 上一章讲了"能力怎么注册"。这一章讲一个更根本的问题：**模型每一轮到底"看到"了什么？** 答案是两个东西：会话日志（历史） + 系统提示（规则与工具说明）。

## 10.1 会话日志：只追加的事件流

`packages/core/session` 拥有 `ctx.sessions`。它维护一份**只追加（append-only）的 `SessionEvent` 日志**。

每一次对话里发生的事——用户发言、模型输出、工具调用、工具结果——都被记成一条**事件（event）**追加进日志：

```
user/message      # 用户说了什么
assistant/chunk   # 模型流式输出的每一小段（保留回放保真）
assistant/message # 模型完整回答
tool/call         # 模型请求调用某工具
tool/result       # 工具返回的结果
turn/start, turn/end, step/start, step/end  # 循环边界
```

关键代码位置：

- `Session.deriveMessages()`：`packages/core/session/src/index.ts`（第 726 行）——从日志投影出"模型可见的历史"。
- `deriveEventMessage()`：`packages/core/session/src/surface.ts`（第 83 行）——单条事件→消息的投影规则，注释明确写着"THE per-node projection rule"。

## 10.2 铁律：Model-visible means logged（模型可见即已记录）

架构文档第 92–96 行有一句非常重要：

> The session log is the source of the context the model sees. `deriveMessages()` projects model history from it… **Model-visible means logged.** Anything that reaches a model request must be reconstructable from the log.

翻译：**模型看到的任何东西，都必须能从日志里重建出来。** 这是一条运行时不变式（runtime invariant），违反它会直接断言失败。

为什么这么严？因为 dsh 把"模型上下文"当成**可重放的事件流**来对待：

- 分叉（fork）会话、恢复（resume）、生成标题、做遥测、持久化——全部可以从这条流派生；
- 如果某个"模型看到的东西"没进日志，上述一切都会失真。

> 小白意义：当你将来想给 dsh 加"新的模型可见输入"（比如长期记忆摘要），正确做法是**新增一种 SessionEvent，并从日志渲染它**，而不是偷偷塞一段变量进 prompt。这是 dsh 最重要的架构纪律。

## 10.3 系统提示：把"规则 + 工具说明"拼起来

`packages/core/system-prompt` 拥有 `ctx.systemPrompt`。它负责在每次模型请求前**组装系统提示**：

1. 收集所有插件注册的**提示段（prompt sections）**——人格设定、行为准则、工具使用说明等；
2. 收集当前可用工具的 **schema（工具说明书）**，让模型知道"自己有哪些手"；
3. 拼成完整系统提示。

这就是为什么你加一个工具，模型"自动"就知道它的存在——工具插件在注册时，同时贡献了一段提示（工具的 JSON schema 与描述），`system-prompt` 包自动把它拼进系统提示。

回到第 2 章的比喻：系统提示不是一句写死的字符串，而是**多个插件各自贡献一段、由框架拼装**的结果。这再次体现了"一切皆插件"。

## 10.4 两者如何一起喂给模型

一个 step 里，模型请求由这些组成（简化）：

```
[系统提示: 人格 + 工具 schema + 行为准则]
[历史消息: 由会话日志 deriveMessages() 投影而来]
[本轮用户输入]
```

框架在 `agent-loop` 的 `preStep()` 阶段调用 `systemPrompt.assemble(...)`，再结合日志派生出的历史，组装成最终请求。下一章看工具、第 13 章看整个循环时，你会看到它们如何串起来。

## 10.5 小结

- 会话日志 = 只追加的 `SessionEvent` 流；`deriveMessages()` 从中投影模型可见历史。
- **模型可见即已记录** 是不可违反的架构铁律；新模型输入 = 新事件 + 从日志渲染。
- 系统提示 = 各插件贡献的提示段 + 工具 schema，由 `system-prompt` 包拼装。

# 第13章 Agent 主循环（turn 流）

> 前面几章分别是"零件"：工具、模型、日志、提示。这一章把它们**真正串起来**：一个 Agent 是怎么从收到一句话，到完成一个多步任务的。这就是 `core/agent-loop`。

## 13.1 两个概念先分清

架构文档（第 65 行）的定义：

- **step（步）**：一次模型请求 + 它发起的工具调用。
- **turn（轮）**：零个或多个 step。从"领取输入"开始，到"没有欠账"（任务完成）关闭。

> 小白记忆：step 是"想一步、做一步"；turn 是"整件事从头到尾"。

## 13.2 默认驱动：ReactLoopAgent

`packages/core/agent-loop` 拥有 `ctx.agentLoop`。它实现了 `Agent` 接口，类名就叫 **`ReactLoopAgent`**——名字里的 ReAct 正是第 3 章讲的"思考→行动→观察"循环。

关键代码位置（`packages/core/agent-loop/src/agent.ts`）：

- `kick()`（第 210 行）：驱动整个循环——`while (await this.turn()) {}`
- `turn()`（第 246 行）：跑一轮
- `preStep()`（第 225 行）：组装提示、领取输入
- `step()`（第 332 行）：一次模型请求 + 工具调用
- `buildRequest()`（第 407 行）：组装冻结的模型请求

## 13.3 一个 turn 的完整事件流

架构文档第 67–82 行给出了权威事件序列，这也是你打开 Web UI 看"工作过程"时能观察到的节奏：

```text
turn/start
  领取下一步输入 + 一条排队消息
  组装提示段 + 工具 schemas
  -> agent/pre-step                 (瀑布：可改写或拒绝)
     · 被拒绝，或首个 enter 被改写为空 → 直接关轮，不花 step
     step/start
     把进入的消息写成 user/message
     从日志派生模型历史（deriveMessages）
     agent/request -> llm/stream -> assistant/chunk* -> assistant/message
     tool/call* -> tools/pre-execute -> tools/execute -> tools/post-execute -> tool/result*
     step/end
     工具还欠一次请求，或又有新输入 → 领取 → 下一个 step
  -> agent/turn-stopping             (串行，无 next())
turn/end
```

## 13.4 逐步拆解：step() 里发生了什么

`step()`（第 332 行）是最核心的一段，简化逻辑：

```ts
// 1) 组装系统提示
const system = renderPrompt(assembly)

// 2) 从会话日志派生模型可见历史（"模型可见即已记录"）
const { request, preparedCall } = await this.buildRequest(
  ..., this.session.deriveMessages(), signal)

// 3) 流式调用模型，并逐块记入日志（保留回放保真）
for await (const chunk of stream) {
  this.session.append('assistant/chunk', { turn, step, chunk })
}

// 4) 组装 assistant/message 入日志
this.session.append('assistant/message', { ... })

// 5) 如果模型发起了工具调用 → 执行工具 → 结果入日志，进入下一步
if (hasToolCall) {
  await executeToolCalls(...)          // tools/pre-execute → execute → post-execute
  this.session.append('tool/result', ...)
}
```

注意第 3 步：模型输出是**流式**的，每一小段（chunk）都被写进会话日志。这样 UI 能实时显示、事后能完整回放——这正是第 10 章"日志是唯一事实来源"的体现。

## 13.5 preStep：决定"模型这一轮看到什么"

在每轮请求前，`preStep()` 会：

1. 从 inbox **领取**待处理输入（一个或多个消息）；
2. 调用 `systemPrompt.assemble(...)` 组装提示段与工具 schema；
3. 经 `agent/pre-step` 事件（瀑布）让插件们**改写或拒绝**这轮输入。

`agent/pre-step` 是 dsh 最常用的扩展点之一——你想"给模型注入一段上下文"，就监听它，把内容加进进入的消息。

## 13.6 事件的水域划分（重要）

架构文档提醒：事件分**持久会话事件**与**实时扩展点**：

- 持久事件（写入日志）：`turn/*`、`step/*`、`user/message`、`assistant/*`、`tool/*`；
- 实时扩展点（不持久）：`agent/pre-step`、`agent/request`、`llm/stream`、`tools/*`——其中前四个是**瀑布**，监听者必须调 `next()` 委托；`agent/turn-stopping` 是**串行**，没有 `next()`。

> 小白意义：想"拦"某个环节，就监听对应事件；但要知道哪些事件会写入日志、哪些只是实时。这决定了你的插件行为是否可回放。

## 13.7 小结

- step = 一次模型请求 + 其工具调用；turn = 一轮完整任务。
- `ReactLoopAgent` 用 `kick → turn → step` 驱动 ReAct 循环。
- 每个 step：组装提示 → 日志派生历史 → 流式调用模型 → 执行工具 → 结果入日志 → 下一 step。
- `agent/pre-step` 是注入/改写模型输入的首选扩展点。

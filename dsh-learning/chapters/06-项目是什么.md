# 第6章 dsh 是什么 & 中心思想

> 终于来到项目本身。这一章回答两个问题：dsh 到底是什么？它的中心思想为什么重要？

## 6.1 dsh 是什么

`dsh`（DeepSeek Harness）是 DeepSeek AI 开源的一个 **agent harness（智能体框架）**。

官方 README 原文：

> DeepSeek Harness (`dsh`) is an open-source agent harness developed by DeepSeek AI.

它的架构特点是：

> **Everything is a plugin（一切皆插件）**，底层由 [Cordis](https://github.com/cordiverse/cordis) 驱动。

也就是说：dsh 不是一个"把功能写死"的程序，而是一个**插件宿主**——模型的适配器、工具注册表、会话日志、甚至 Agent 主循环，都是插件。

## 6.2 中心思想：一切皆插件

这句话是理解整个项目的钥匙。展开说三层含义：

### 1) 能力以"插件"为单位存在

每个能力（一个工具、一个 LLM 适配器、一段提示、一个记忆后端）都写成一个 Cordis 插件。插件向一个**共享上下文（context）**贡献三样东西：

- **服务（services）**：比如 `ctx.tools`、`ctx.llm`、`ctx.sessions`；
- **类型化事件（typed events）**：比如 `agent/pre-step`、`tools/execute`、`session/event`；
- **可逆 effect**：插件卸载时统一回滚的注册。

### 2) 没有"特权核心"需要你去 patch

架构文档里有一句很关键的话：

> There is no privileged core to patch: you extend dsh by mounting a plugin beside the others, and registrations are effects that unwind when their plugin unloads.

意思是：**核心不给你留"特殊后门"让你改**；你要扩展，就在别的插件旁边**挂一个自己的插件**。这样做的好处是——核心保持稳定，你的扩展和核心解耦。

### 3) 组合来自配置，不来自改码

一个跑起来的 dsh，是一棵在启动时按层**组合（compose）**出来的插件树。它由 **profile（配置组合模板）** 和 **bundle（可分发的能力包）** 描述。你想换默认人设、加工具，靠的是**写配置/preset**，不是改 `packages/` 里的核心代码。

## 6.3 Cordis 是什么（一句话）

Cordis 是 dsh 底层的**插件框架**，设计源自论文《A Programming Paradigm for Spatiotemporal Composability》。它提供：插件契约、`ctx` 服务仓库、依赖注入（通过 `inject`）、类型化事件、可逆 effect。

- 入门文档：`docs/cordis-primer.md`
- 源码位置：`vendor/cordis/src/`（dsh 把它 vendored 并重命名为 `@deepseek-ai/cordis`）

> 你不需要现在就读懂 Cordis 全部源码。第 9 章会专门讲它的内核。本章只要记住：**dsh = Cordis 上长出来的一堆插件**。

## 6.4 用一句话总结 dsh

> dsh 是一个**以 Cordis 为底座、以"插件"为唯一扩展方式**的智能体框架；你用它，就是**在插件系统之上，组装出属于你的 Agent**。

## 6.5 为什么这个中心思想对你最重要

回到你的目标（终身个人 Agent）：**"一切皆插件"恰恰把"扩展"这件事标准化了**。你不用学习"这个项目有哪些隐藏的扩展点"，你只需要学会"怎么写一个插件"——一种模式，处处适用。这正是后续实战章节会反复用到的同一套套路。

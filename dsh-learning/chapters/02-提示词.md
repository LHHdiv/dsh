# 第2章 什么是提示词（Prompt）

> 上一章我们把大模型比作"蒙眼的天才学者"。这一章讲：**你怎么跟他有效对话**——这就是提示词（Prompt）。

## 2.1 提示词是什么

**提示词（Prompt）** 就是你发给大模型的"任务说明书"。模型的一切输出，都是基于这段说明书 + 它训练中学到的规律，逐字预测出来的。

一句话：**你给的提示，决定了模型扮演谁、做什么、以什么格式回答。**

## 2.2 两类提示

在一个 Agent 系统里，提示通常分两层：

| 类型 | 谁写的 | 作用 | 例子 |
|---|---|---|---|
| **系统提示（System Prompt）** | 开发者/框架 | 设定角色、规则、可用工具 | "你是一个严谨的编程助手，只能用中文回答" |
| **用户提示（User Prompt）** | 用户 | 这一次具体要做什么 | "帮我写一个快速排序" |

在 dsh 里，系统提示不是一句写死的字符串，而是由**多个"提示段（prompt sections）"拼装**而成——这正是后面 Part 2 第 10 章要讲的 `system-prompt` 包。你加一个工具，框架就自动把该工具的"说明书"拼进系统提示，模型于是"知道"自己多了一双手。

## 2.3 写好提示的几个关键技巧

### 角色设定（Persona）

通过系统提示告诉模型"你是谁"：

```text
你是一位资深的 PostgreSQL 数据库工程师，回答必须给出可执行的 SQL，
并解释每个索引的取舍。
```

### 结构化输出

明确格式，能大幅降低模型"自由发挥"带来的不稳定：

```text
请用 JSON 返回：{"summary": "一句话总结", "steps": ["步骤1","步骤2"]}
```

### 少样本（Few-shot）

给一两个例子，模型会"照着学"：

```text
把口语改成正式邮件。
例：
输入：哥们帮我看下这报表
输出：烦请协助审阅附件中的报表，谢谢。
输入：这事儿急，尽快
输出：？
```

## 2.4 提示词与"可控性"

提示词是**最便宜的改模型行为的方式**——不用改一行代码，只改文字。但提示词也有局限：

- 它**管不住模型去调工具**（那是工具系统的事）；
- 它**记不住跨会话的事**（那是记忆的事）；
- 长提示会**占满上下文窗口**，挤掉真正重要的内容。

所以，一个成熟的 Agent 框架，会把"提示词的拼装"做成**结构化、可插拔**的能力——谁提供一个能力，谁就贡献一段提示。这正是 dsh "一切皆插件"思想的体现之一。

## 2.5 dsh 里提示词长什么样（先睹为快）

在 dsh 的预设文件 `apps/cli/config/agent-presets/standard/agent.cordis.yml` 里，你会看到类似：

```yaml
- id: persona
  name: '@deepseek-ai/dsh-persona'
- id: agent-instructions
  name: '@deepseek-ai/dsh-agent-instructions'
```

这些就是"提示段"的提供者。框架在每次模型请求前，把它们**组装**成完整的系统提示。你后面学 `system-prompt` 包时会明白这套机制。

## 2.6 小结

- 提示词 = 给模型的任务说明书；分系统提示（角色/规则）与用户提示（具体任务）。
- 写好提示靠：角色设定、结构化输出、少样本。
- 提示词便宜但有限；真正的"能力扩展"要靠工具与框架。

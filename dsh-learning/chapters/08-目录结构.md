# 第8章 目录结构与文件含义

> 这一章像一张"地图"，带你逐一看懂 dsh 顶层目录与 `packages/` 里的关键包。读源码时，你可以随时回来查。

## 8.1 顶层目录速览

| 目录 | 作用 |
|---|---|
| `packages/` | **所有 harness 功能包**，每个都是 `@deepseek-ai/dsh-*` 插件（core、llm、tools、preset…） |
| `vendor/` | **源码级内联的 Cordis 框架**及基础库（cosmokit、schemastery 等），重命名为 `@deepseek-ai/*` |
| `docs/` | 架构、教程、子系统、配置目录、cookbook 等文档（`cordis-primer.md`、`architecture.md` 在此） |
| `apps/` | 可部署入口：`apps/cli`（`dsh` 命令行）、`apps/cli/config/agent-presets`（**出厂预设**目录） |
| `examples/` | 可独立运行的示例组合（headless-agent、acp-agent、web-cordis…），各含 `cordis.yml` |
| `scripts/` | 仓库脚本（门禁、发布、vendor 同步等） |
| `python/` | Python 侧运行时/SDK（如 `python/sdk-runtime`） |
| `native/` | 原生/Node 插件（如 `native/landlock-run` 沙箱） |
| `.agents/` | Agent 笔记与技能（架构决策记录、实现笔记） |

## 8.2 `packages/` 主要分组与角色

`packages/` 按"能力"分包，每个包只拥有自己那一块 `ctx` key。下面按你学习的优先级列出**最关键**的包（路径均为相对仓库根）：

### core（核心循环与状态）

| 包路径 | 拥有 | `ctx` key |
|---|---|---|
| `packages/core/session` | 只追加的 `SessionEvent` 日志与内存存储 | `ctx.sessions` |
| `packages/core/system-prompt` | 提示段与工具 schema 组装 | `ctx.systemPrompt` |
| `packages/core/tools` | 作用域化工具注册表 + 带保护执行管线；`defineTool()` 在此 | `ctx.tools` |
| `packages/core/agent` | `Agent` 接口、活动注册表与 `agent/*` 事件 | `ctx.agents` |
| `packages/core/agent-loop` | 默认驱动（实现 `Agent` 接口） | `ctx.agentLoop` |
| `packages/core/scope` | 每个 agent 的作用域注册原语（库，无 key） | — |

### llm（模型层）

| 包路径 | 作用 |
|---|---|
| `packages/llm/llm` | 消息/流词汇 + 适配器接口（`ctx.llm`、`LlmRuntime`） |
| `packages/llm/llm-deepseek` | DeepSeek 适配器（注册到 `ctx.llm`） |
| `packages/llm/llm-retry`、`llm-pi-ai`、`token-meter` | 重试、备选 provider、tokens 计量 |

### 能力与 Provider

- `packages/skill/`：技能目录与加载（`skill-filesystem`、`tool-skill`）。
- `packages/fs/`：文件系统访问（`tool-fs`、`tool-str-replace-editor`、`fs-local`）。
- `packages/shell/`：Shell 执行（`bash-local`、`pwsh-local`、`tool-bash`）。
- `packages/terminal/`：持久终端（`ctx.terminals`）。
- `packages/subagent/`：子代理（`subagent`、`tool-subagent`）。
- `packages/workflow/`：工作流引擎（`workflow-worker-thread`、`tool-workflow`）。

### 配置与组合

- `packages/preset/agent-presets`：预设解析/挂载（`ctx.agentPresets`）。**第 14 章重点。**
- `packages/settings/settings-file`：读取 `settings.yaml`。
- `packages/credentials/`：凭据存储。
- `packages/interaction/`：审批/交互（`tool-ask-user`）。
- `packages/hooks/`：钩子机制。
- `packages/acp/`、`packages/sdk/`：Agent Client Protocol 与 SDK。

### 你之前做过的包

- `packages/notes/tool-my-notes`：你写的私有工具（读 `~/dsh-notes` 笔记）。**第 15 章详解。**
- `packages/todo/tool-todo`：最规范的"整体列表替换"工具范例，适合对照学习。

## 8.3 `vendor/cordis` 是什么

`vendor/cordis/src/` 是 Cordis 框架源码（`index.ts`、`context.ts`、`events.ts`、`registry.ts`、`service.ts`、`fiber.ts` 等）。dsh 把它**内联**进仓库（而非当作普通 npm 依赖），以便精确控制版本与打补丁。你在第 9 章会用到它。

## 8.4 出厂预设在哪

`apps/cli/config/agent-presets/standard/` 是**出厂预设**目录，里面有：

- `agent.cordis.yml`：组合了身份、shell、文件系统、后台任务、技能等插件与工具；
- `preset.yml`：预设的元数据（`name`/`description`/`order`）。

你之前复制它、改成自己的 `my-personal`，就是"不改核心、只加配置"的典型操作。

## 8.5 读源码的建议顺序

1. 先读 `docs/cordis-primer.md`、`docs/architecture.md`（概念）；
2. 再读 `packages/core/session`、`packages/core/tools`、`packages/core/agent-loop`（主干）；
3. 然后 `packages/preset/agent-presets`、`packages/settings/settings-file`（配置与组合）；
4. 最后挑一个工具包（`tool-todo` 或你写的 `tool-my-notes`）通读。

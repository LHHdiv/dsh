# 导读：本书怎么读、你将学会什么

> 这不是一份官方文档的翻译，而是一份**陪你从零学、并带你动手改代码**的教练式教程。
> 你不需要是专业开发者——本书的目标，就是帮你在读的过程中，逐渐变成能维护、能扩展 dsh 的专业人员。

## 这本书写给谁

- 你**拿到了 dsh 这个项目**，但还不懂它是什么、代码怎么组织；
- 你希望它未来成为**你个人终身迭代、更新的 Agent**；
- 你**不是专业开发者**，但想通过学习这个项目，成长为能独立维护代码的人。

如果你的画像符合以上三点，那么这本书就是为你写的。

## 本书的四条约定

1. **先懂「为什么」，再写「怎么做」**。每一处代码改动，我都会先讲清楚改动的逻辑，再贴出代码逐行讲解——因为你学的是"思考方式"，不是"照抄命令"。
2. **图文与比喻优先**。抽象概念（大模型、Agent、插件、生命周期）先用生活比喻讲通，再落到源码与文件路径。
3. **单一信息源、可离线**。所有内容以 Markdown 写成，由 `build.py` 生成可双击打开的 HTML；你随时能离线翻看。
4. **改动即学习**。当你读到"实战"章节，会真的改一点点代码、加一个私有工具，并理解每一行的含义。

## 一个重要的现实提醒

dsh 目前处于 **developer preview（开发者预览）** 阶段，官方明确说明：**未来会有破坏性变更（compatibility-breaking changes）**。

这意味着：

- 不要死记某个 API 的名字，而要**理解它的架构与扩展机制**——机制稳定，具体函数名会变。
- 它现在是"简单"的，这恰好是**学习的好时机**：你能看清全貌，而不是淹没在庞大代码里。
- 你做的一切扩展，应当**挂成插件（plugin）**，而不是去改核心——这样将来升级时，你的改动不会被覆盖。

## 建议的阅读方式

1. **按顺序读**：Part 0 → Part 3，不要跳。前面是后面的地基。
2. **边读边跑**：Part 1 第 7 章会教你把项目跑起来，之后每读一章，都可以打开对应的源码文件对照看。
3. **动手优先**：遇到"实战"章节，请真的照着改一次代码——改错也没关系，那正是学习发生的地方。
4. **善用目录**：每章左侧有"本页大纲"与"全书章节"，可随时跳读。

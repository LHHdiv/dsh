# 第3章 什么是指令循环与 Agent

> 提示词解决了"怎么跟模型说话"，但还缺两样东西：**手（工具）** 和 **循环（多步思考）**。
> 把"模型 + 工具 + 循环"装到一起，就是 **Agent（智能体）**。

## 3.1 一个朴素的困惑

你问大模型："帮我查一下明天北京飞上海的航班，再订最便宜的那班。"

单靠提示词，模型只能**口头**给你一个"建议方案"——因为它**没有手**去查航班、**没有手**去下单。它只是把训练里见过的类似回答"预测"出来，可能还是编的（幻觉）。

要让它**真的办成事**，必须给它：

1. **工具（Tools）**：查航班 API、下单接口；
2. **循环（Loop）**：先想"我该先查航班"，调工具拿到结果，再看结果决定"订哪一班"，再调下单工具。

这就是 **Agent** 的核心。

## 3.2 Agent = 模型 + 工具 + 循环

```
        ┌─────────────┐
        │   用户目标   │
        └──────┬──────┘
               ▼
        ┌─────────────┐
        │  思考(模型)  │◄──────────┐
        └──────┬──────┘           │
               │ 需要查/做某事     │ 观察结果
               ▼                  │
        ┌─────────────┐           │
        │  调用工具    │           │
        └──────┬──────┘           │
               │ 返回结果          │
               └──────────────────┘
```

这个"**思考 → 行动 → 观察 → 再思考**"的圈，就是经典的 **ReAct（Reasoning + Acting）循环**。

- **思考**：模型读上下文，决定下一步（继续回答 / 调某个工具）；
- **行动**：框架执行模型选中的工具，把参数传进去；
- **观察**：工具结果回到上下文；
- 模型基于新信息**再思考**，直到认为任务完成，给出最终回答。

## 3.3 为什么"循环"是关键

没有循环，模型只能"一问一答"——一次预测就结束。有了循环，它就能把**复杂任务拆成多步**，一步步逼近目标：

> 目标：订最便宜的航班
> 第1步思考：先查航班 → 调 `search_flights` → 观察：返回 5 个航班
> 第2步思考：比较价格 → 选最低 → 调 `book_flight` → 观察：订成功
> 第3步思考：任务完成 → 回答用户："已为你预订……"

**多步、带工具、能根据中间结果调整策略**——这就是 Agent 区别于"普通聊天机器人"的本质。

## 3.4 Agent 不是万能的

作为学习者，要客观看待 Agent：

- 它会**犯错**：可能选错工具、传错参数；
- 它需要**护栏**：哪些工具能调、调用要不要人审批，必须有人把关（dsh 里有 approval/interaction 机制）；
- 它受**上下文窗口**限制：步骤太多会"忘记"开头；
- 它**不会自我修复架构**：Agent 的智能来自循环，但循环本身由框架（Harness）提供。

所以下一章我们要讲：**谁来把"模型、工具、循环、记忆、护栏"稳稳地组装起来？** 答案是 **Harness（框架）**。

## 3.5 小结

- Agent = 模型 + 工具 + 循环（ReAct）。
- 循环让模型能把复杂任务拆成多步、根据结果调整。
- Agent 需要护栏与记忆，而这些由框架提供。

> 下一章：把模型、工具、记忆、上下文、UI 组装成一辆能开的"车"——这就是 **Harness**。

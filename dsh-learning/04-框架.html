没有车架，发动机、轮子、传动就是一堆散件，跑不起来；没有 Harness，Agent 就是一段跑不通的脚本。

🎯
本文学系目标理解 Harness 的作用：把模型、工具、记忆、上下文串成一辆可驾驶的「车」。

第4章 什么是 Harness（智能体框架）

现在你有了：模型（大脑）、工具（手）、循环（多步思考）。把它们稳稳组装成一辆能开的车，这件事由 Harness（框架/外壳） 负责。

4.1 一个生活比喻

  • 大模型 = 发动机（提供动力/智能）；
  • 工具 = 车轮、方向盘、油箱（执行部件）；
  • 循环 = 传动系统（让发动机驱动车轮）；
  • Harness = 整辆车架 + 仪表盘 + 安全带——把上面所有东西按正确方式装起来，让你能安全驾驶。

没有车架，发动机、轮子、传动就是一堆散件，跑不起来；没有 Harness，Agent 就是一段跑不通的脚本。

4.2 Harness 到底做了什么

一个称职的 Agent 框架（Harness）至少要解决这些问题：

问题 Harness 提供的答案
工具从哪来、怎么注册？ 工具注册表（dsh 里是 ctx.tools）
模型怎么被调用、流式输出怎么处理？ LLM 能力层（dsh 里是 ctx.llm）
对话历史存在哪、模型看到什么？ 会话日志（dsh 里是 ctx.sessions，只追加的事件流）
一轮"思考→工具→观察"怎么驱动？ Agent 主循环（dsh 里是 ctx.agentLoop）
谁来决定默认人设、加载哪些工具？ 预设系统（dsh 里是 ctx.agentPresets）
调危险工具前要不要人审批？ 交互/审批机制（dsh 里 interaction 包）
换一个模型、加一个工具，要改核心吗？ 插件化：挂上即可，核心不动

你会发现，右边那一列全是 dsh 的包。也就是说：dsh 本身，就是一个 Harness。而它的特别之处在于——这些"车架部件"本身，也都是插件。

4.3 为什么"框架"值得单独存在

你当然可以不用框架，自己写：

while True:
    resp = call_llm(history)
    if resp.has_tool_call:
        result = run_tool(resp.tool, resp.args)
        history.append(result)
    else:
        print(resp.text); break

几十行就能跑通一个玩具 Agent。但当你要：支持 30+ 工具、流式输出、会话持久化、多 Agent 协作、用户审批、可插拔扩展、Web UI……自己写的脚本会迅速变成无法维护的意大利面。

Harness 的价值，正是把"通用且易错"的部分抽象成稳定能力，让你只关心"我要加什么新能力"。

4.4 dsh 作为 Harness 的独特之处

dsh 不只是一个"能跑 Agent 的框架"，它的设计哲学是：

Everything is a plugin（一切皆插件）。

这意味着：模型适配器、工具注册表、会话日志、Agent 主循环——连循环本身都是插件。你扩展 dsh，不是去改核心源码，而是在旁边挂一个插件。插件卸载时，它的所有注册会统一回滚（可逆 effect）。

这一点，对你这个"想终身迭代个人 Agent"的人来说，至关重要——它在架构层面保证了可成长性。

4.5 小结

  • Harness = 把模型、工具、循环、记忆、护栏组装成可用系统的"车架"。
  • 它解决了注册、调用、日志、循环、预设、审批等通用难题。
  • dsh 本身就是一个 Harness，且"连循环都是插件"，天生为扩展而设计。
